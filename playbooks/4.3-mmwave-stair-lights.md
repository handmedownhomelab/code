# Playbook 4.3 — mmWave radar stair lights

> **For the reader.** Read this whole file before you give it to your AI
> assistant. You need Home Assistant from playbook 4.1, an **HLK-LD2450**
> radar module, an ESP32 development board (the book's is an `esp32dev`),
> four jumper wires, a USB cable and a 5 V supply, and a light Home
> Assistant can switch. You do the wiring and plug the board in. Then say:
> *"Follow this playbook. Ask me before every step marked CONFIRM."*
>
> **For the AI assistant.** You are helping a reader of *Hand-Me-Down
> Homelab* build what section 4.3 describes. Follow the rules below for the
> whole session.

## Rules for the assistant

1. **Discover, don't assume.** Use the reader's board, pins, Wi-Fi and
   light.
2. **Show each command and file before you use it.**
3. **CONFIRM** before flashing a board and before changing a working
   automation.
4. **Wi-Fi credentials go in ESPHome's `secrets.yaml`**, typed by the
   reader, referenced as `!secret`. Never in the device YAML, never in git,
   never in your output.
5. **Home Assistant changes go through its web interface or its API**,
   never by editing files under `.storage`.
6. **Verify by effect**: the target count moving as someone walks, the
   light on the stairs.

## Goal: what "done" looks like

- [ ] The LD2450 is wired to the ESP32 (5 V, ground, TX and RX) and the
      board runs ESPHome, updated over Wi-Fi from then on.
- [ ] Home Assistant shows the device, with a *Total Targets* sensor that
      rises as people step on the stairs and returns to 0 when they leave.
- [ ] One automation turns the stair light on when the count rises above 0
      (a numeric-state trigger); another turns it off at 0.
- [ ] Detection zones are trimmed so walking past the bottom of the stairs
      doesn't light them.
- [ ] The device YAML is in git, without `secrets.yaml`.

## Discover first

| What | Why | How to find it |
|---|---|---|
| The ESP32 board type | ESPHome's `board:` | Printed on the board or its listing (`esp32dev` is the common one) |
| Two free UART pins | The radar's serial lines | The board's pinout; the book uses GPIO16 (RX) and GPIO17 (TX) |
| The Wi-Fi network for the board | It joins over Wi-Fi | Ask; an IoT network (playbook 1.6) if you have one, and Home Assistant must be able to reach it |
| The stair light's entity | The automations | Settings → Devices & services → Entities |
| A git hub to push to | Backups of the YAML | Playbook 2.2's hub, or any |

## Steps

### 1. Wire it — the reader

Four wires, board unplugged:

| LD2450 | ESP32 |
|---|---|
| 5V | 5V (VIN) |
| GND | GND |
| TX | GPIO16 (the board's RX) |
| RX | GPIO17 (the board's TX) |

TX goes to RX: the radar's transmit line is the board's receive pin.

### 2. The ESPHome add-on — the reader, in Settings → Add-ons

Install **ESPHome Device Builder** and open it. In its *Secrets* editor
the reader adds `wifi_ssid` and `wifi_password` (rule 4).

### 3. The device YAML

New device in the add-on, then replace its YAML with this (names are the
book's; keep the `api:` and `ota:` blocks the add-on generated, including
any encryption key):

```
esphome:
  name: ld2450-mmwave
esp32:
  board: esp32dev
wifi:
  ssid: !secret wifi_ssid
  password: !secret wifi_password
logger:
api:
ota:
  - platform: esphome
uart:
  id: uart_ld2450
  rx_pin: GPIO16
  tx_pin: GPIO17
  baud_rate: 256000
ld2450:
  uart_id: uart_ld2450
sensor:
  - platform: ld2450
    target_count:
      name: "mmWave Total Targets"
    still_target_count:
      name: "mmWave Still Targets"
    moving_target_count:
      name: "mmWave Moving Targets"
```

The LD2450 talks at **256000** baud; a different rate reads nothing. Add
per-target `x`, `y` and `speed` sensors (the component page lists them)
if you want to see where each person is; they help with step 6.

**Verify:** the add-on's *Validate* passes.

### 4. Flash it — CONFIRM

The first flash is over USB: plug the board into the computer running the
browser and use *Install → Plug into this computer* (the browser needs to
reach Home Assistant over HTTPS for this; the proxy from 4.1 provides it),
or ESPHome's web installer. Every flash after that is over Wi-Fi from the
add-on (*Install → Wirelessly*). Then power the board from its 5 V supply
where it will live, looking at the stairs.

**Verify:** the add-on shows the device *Online*, and its logs show LD2450
target lines. Give the board a DHCP reservation (book 1.5).

### 5. Adopt it

Home Assistant discovers the board: Settings → Devices & services →
*Discovered* → ESPHome → Configure (with the encryption key if asked).

**Verify:** the device page shows *mmWave Total Targets*. Watch it while
someone walks onto the stairs, **stops**, and walks on: it stays above 0
while they stand still. That's the difference from a PIR motion sensor,
which sees only movement.

### 6. Trim the zones

As installed, the radar also sees people walking past the bottom of the
stairs. Trim its detection area to the stairs: the LD2450 supports zones,
which ESPHome's `ld2450` component can expose as settings (see its page
for the `zone_type` select and the zone corner numbers), or set them in
the manufacturer's phone app over Bluetooth.

**Verify:** walk past the bottom without stepping on: the count stays at
0. Step on: it rises.

### 7. Two automations — CONFIRM

```
alias: Stairs light on
mode: single
triggers:
  - trigger: numeric_state
    entity_id: sensor.ld2450_mmwave_mmwave_total_targets
    above: 0
actions:
  - action: switch.turn_on          # or light.turn_on
    target:
      entity_id: switch.stairs_led
```

and the same with `below: 1` and `switch.turn_off`. No timers and no
"still there?" delays: the radar still sees someone pausing halfway up.

Use the **numeric-state** trigger. A state trigger from `0` to `1` (the
obvious one, and the one the book's first version had) never fires when two
people step on together, because the count goes straight from 0 to 2.

**Verify:** the light comes on as someone steps on, stays on while they
stand still, and goes off when the last person leaves. Then two people
step on together: it still comes on.

### 8. Put the YAML in git — CONFIRM where it pushes

In the add-on's folder (`/config/esphome/` in Home Assistant, reached with
the SSH add-on), make a git repository and push it to the reader's hub.
ESPHome's own `.gitignore` there leaves out `secrets.yaml` and its build
cache; check that before the first commit (`git status` must not list
`secrets.yaml`). A readable copy in the wiki is a good second backup.

**Verify:** a fresh clone from the hub has the device YAML and no
`secrets.yaml`.

## Gotchas (from the book and the author's lab)

- **Retire boards in Home Assistant too.** Three retired ESP32 devices kept
  logging reconnection failures at old addresses for weeks. Disable their
  integration entries. A `disabled_by: user` flag on them is deliberate;
  don't "fix" it by re-enabling them.
- **0 → 2 skips a 0 → 1 trigger** (step 7).
- **TX to RX.** A radar wired TX-to-TX validates and flashes fine, and
  reports nothing.
- **Name it before adopting.** The entity IDs come from the ESPHome node
  name and sensor names; renaming later ripples through automations.

## Rollback

Disable the two automations. Delete the device in Settings → Devices &
services → ESPHome, and in the add-on.
