# Playbook 7.6 — ACE-Step

> **For the reader.** Read this whole file, and the files in `7.6/`, before
> you give them to your AI assistant. You need the GPU box from book 7.1,
> about 20 GB of free disk, SSH from your workstation to the GPU box by
> key, and `ffmpeg`. If Ollama, Forge or ComfyUI (7.2–7.4) run on the same
> card, this one takes turns with them. It is **Not tested** (see the
> header). Then say: *"Follow this playbook. Ask me before every step marked
> CONFIRM."*
>
> **For the AI assistant.** You are helping a reader of *Hand-Me-Down
> Homelab* build what section 7.6 describes. Follow the rules below for the
> whole session.

## Rules for the assistant

1. **Discover, don't assume.** Card memory, the CUDA version and what else
   uses the card decide the PyTorch build and whether offload is needed (on
   a 16 GB card it is; see step 4).
2. **Show each command before you run it**, and say which machine it runs
   on: the GPU box or the workstation.
3. **CONFIRM** means stop, ask, and wait for a yes. Anything that installs
   software, downloads gigabytes, stops another program's model, or deletes
   anything is a CONFIRM step even if this file forgot to mark it.
4. **Get install steps from ACE-Step's README**; they change. Don't pipe
   downloaded scripts into a shell.
5. **ACE-Step listens on 127.0.0.1 only.** Reach it through an SSH tunnel;
   add no firewall rule.
6. **Verify by effect**: a track you have listened to (the reader) and
   measured (you: duration and loudness with ffmpeg).
7. If the reader keeps a homelab wiki, record the install path, the
   PyTorch, torchaudio, torchcodec and gradio versions, the launcher, and
   every program the launcher stops.

## Goal: what "done" looks like

- [ ] ACE-Step runs from its own Python 3.10 venv on the GPU box, with a
      PyTorch build for the card and matching torchaudio and torchcodec.
- [ ] It is only ever started by `acestep-run.sh`: every Ollama model
      unloaded, the other GPU apps stopped, CPU offload on, listening on
      127.0.0.1.
- [ ] `music` on the workstation opens a tunnel, starts ACE-Step, opens the
      browser; Ctrl-C stops it and loads the chat model back.
- [ ] A song with lyrics made in the web interface, and two tracks made by
      `acestep_batch.py` from a job file.

## Discover first

| What | Why | How to find it |
|---|---|---|
| Card memory, and what's using it | With offload, about 8 GB at peak; without, about 15 GB | `nvidia-smi`; `ollama ps` |
| The CUDA version the driver supports | Decides the PyTorch build | `nvidia-smi` header |
| Other GPU apps, and how each is started | The launcher must stop them | Ask; `nvidia-smi` process list |
| The chat model to load back, and its callers | They pay a cold load otherwise | `ollama ps`; book 7.7 |
| Scheduled GPU jobs (photo tagging, nightly batches) | Don't plan music sessions over them | Ask; `systemctl list-timers` |
| Free disk | About 8 GB of checkpoints and 8 GB of venv, plus audio | `df -h ~` |

## Steps

### 1. Install — CONFIRM

On the GPU box, as the reader's user:

```
git clone https://github.com/ace-step/ACE-Step ~/ACE-Step
```

Make a **Python 3.10** venv at `~/ACE-Step/.venv` with uv (`uv venv
--python 3.10`; uv fetches 3.10 if the system has a newer Python). In it,
install PyTorch, torchaudio and **torchcodec** from PyTorch's index for the
reader's CUDA version (the book's: cu130), then ACE-Step itself as its
README says (an editable install of the repository). Then hold gradio
below 6: `uv pip install 'gradio<6'`.

Why each extra:

- **torchcodec:** recent torchaudio writes WAV files through it, and
  ACE-Step's requirements don't list it. Without it, a generation runs to
  the end and then fails at the save step.
- **Matching builds:** torchcodec built for one CUDA version won't load
  against torch built for another.
- **gradio below 6:** gradio 6 dropped an option ACE-Step's interface
  passes, and the interface won't start.

**Verify:** `~/ACE-Step/.venv/bin/python -c 'import torch, torchaudio, torchcodec, gradio; print(torch.__version__, torchaudio.__version__, torchcodec.__version__, gradio.__version__, torch.cuda.is_available())'`
shows the same CUDA tag on the first three, gradio 5.x and `True`.

### 2. The launcher — CONFIRM

Copy `7.6/acestep-run.sh` to `~/acestep-run.sh` on the GPU box, make it
executable, and set `CHAT_MODEL` and `OTHER_GPU_APPS`. If the reader built
7.3 and 7.4, add ACE-Step to *their* launchers' `OTHER_GPU_APPS` too (the
companion copies already list it), so whichever starts last frees the card.

**Verify:** `bash -n ~/acestep-run.sh` passes.

### 3. The tunnel and first run — CONFIRM (stops the chat model)

Source `7.6/music.zsh` from `~/.zshrc` on the workstation, with `GPU_HOST`
and `CHAT_MODEL` set, and run `music`.

**Verify:**
- The browser opens `http://localhost:7861` within about 15 s.
- On the GPU box, `ss -ltn | grep 7861` shows `127.0.0.1:7861` only, and
  `pgrep -af 'ACE-Step/[.]venv/bin'` shows the full path.
- Idle, the app holds well under 1 GB of VRAM: the model loads at the first
  generation, not at start.

### 4. A first song, with offload measured

In the interface: tags in the prompt box (`upbeat, synth-pop, female
vocals, 120 bpm`), lyrics with structure markers (`[verse]`, `[chorus]`,
`[bridge]`), 30–60 seconds, generate. The first generation downloads the
checkpoints (about 8 GB) into `~/.cache/ace-step/checkpoints`.

While it runs, watch the peak on the GPU box:
`nvidia-smi --query-gpu=memory.used --format=csv -lms 500`.

**Verify:** the track plays, the vocals follow the lyrics and sections, and
the peak was around 8 GB (the book's: 7.9 GB, 44 s for one track; without
offload it was 15.2 GB and 54 s, with a near out-of-memory error). Copy the
track to the workstation and check it with
`ffmpeg -i <track>.wav -af volumedetect -f null /dev/null`: a healthy track
reads around `mean_volume: -13 dB` with `max_volume` near 0.

Then Ctrl-C in the `music` terminal. **Verify** no ACE-Step process is left,
the memory is freed, and `ollama ps` shows the chat model again within a few
minutes.

### 5. Batches from a job file

Copy `7.6/acestep_batch.py` to `~/acestep_batch.py` on the GPU box. Write a
job file with two variants of the same tags and different seeds (the
script's header shows the format). Free the card the way the launcher does
(stop the chat model and the other GPU apps), then:

```
cd ~/ACE-Step && ./.venv/bin/python ~/acestep_batch.py job.json
```

Load the chat model back afterwards.

**Verify:** two WAVs in `~/ACE-Step/bench/`, each the requested length
(`ffprobe`), sounding different, and nothing new in `outputs/`.

## Gotchas (from the book and the author's machine)

- **Offload is faster, not just safer**, on a card that also holds other
  work. The launcher and the batch script always use it.
- **Never put your own files in `outputs/`.** The interface reads the names
  of `outputs/*.json` at startup, expecting its own pattern; any other name
  crashes it with a traceback that doesn't say why. Use `bench/` for
  scripts and scratch.
- **`infer.py` makes a random demo song.** Run without arguments it picks a
  preset from the repository's examples: a smoke test, not your track. Use
  the batch script for directed output.
- **Bracket `pkill` patterns sent over ssh** (`ACE-Step/[.]venv/bin`). The
  remote shell's own command line contains the pattern, so an unbracketed
  one kills that shell; ssh exits 255 and everything after the `pkill` is
  silently skipped, including loading the chat model back.
- **The launcher must exec by absolute path.** Started as
  `./.venv/bin/acestep`, the process's command line is relative, and every
  stop that matches `ACE-Step/.venv/bin` misses it.
- **A dependency refresh can break the interface** by pulling gradio 6 or a
  torchcodec that doesn't match torch. Check the versions line from step 1
  first.
- **LoRAs:** only one official one exists for v1 (RapMachine). The
  "Text2Samples" and "Lyric2Vocal" in the README were never released. For
  instrumentals, put `[inst]` in the lyrics. Third-party LoRAs built for
  v1.5, XL or turbo models don't fit v1, and several imitate real artists.
- **Publishing:** read the model's license, listen for anything that sounds
  like a real artist or lyric, and keep real people's names out of the
  lyrics (book 7.6).

## Rollback

Stop ACE-Step. Remove `~/ACE-Step` (keep any tracks you want from
`outputs/` and `bench/` first), `~/.cache/ace-step`, `~/acestep-run.sh`,
`~/acestep_batch.py`, and the `music.zsh` line in `~/.zshrc`. Nothing was
opened in the firewall.
