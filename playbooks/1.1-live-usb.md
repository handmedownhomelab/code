# Playbook 1.1 — Appraise an old computer from a live USB

> **For the reader.** Most of this runs at the old computer's own keyboard
> and screen, so you do the steps and your AI assistant guides you. Read the
> whole file first. Then say: *"Follow this playbook. Ask me before every
> step marked CONFIRM."* After step 5 the assistant can work on the old
> machine directly over SSH, if you want it to.
>
> **For the AI assistant.** You are helping a reader of *Hand-Me-Down
> Homelab* appraise a computer they haven't installed Linux on. Follow the
> rules below for the whole session.

## Rules for the assistant

1. **Nothing is installed on the old computer.** A live session runs from
   the USB stick. Never start the desktop's *Install Linux Mint* icon, and
   never partition, format or write to the internal disk.
2. **Writing the image erases the USB stick.** CONFIRM which device is the
   stick before writing, by its size and name, and that nothing on it is
   needed.
3. **Get the image from linuxmint.com and check its SHA256** against the sum
   on the download page before writing it.
4. **Show each command before you run it**, and say which machine it runs on.
5. **Verify by effect:** the stick boots, the commands return real values,
   and a missing virtualization flag is re-checked after any firmware change.

## Goal: what "done" looks like

- [ ] A USB stick that boots Linux Mint in a live session.
- [ ] The old computer booted from it, with its internal disk untouched.
- [ ] Its processor, virtualization flags, memory, disks and disk health
      recorded, with a verdict on its binding constraint.
- [ ] The result saved as the machine's first wiki page (Chapter 2).

## What you need

- A USB stick of **8 GB or more** that you can erase.
- Any working computer to download and write the image (Windows, macOS or
  Linux).
- The old computer, with a keyboard, screen and, ideally, a wired network
  connection.
- Not supported: Apple Silicon Macs (M1 and later) can't run Linux Mint.

## 1. Download Linux Mint and check it

On the working computer, download the **Cinnamon** edition from
linuxmint.com/download.php. Note the SHA256 sum the page publishes, then:

- **Windows (PowerShell):** `Get-FileHash .\linuxmint-*.iso -Algorithm SHA256`
- **macOS:** `shasum -a 256 linuxmint-*.iso`
- **Linux:** `sha256sum linuxmint-*.iso`

The sums must match. If they don't, download it again. Linux Mint's guide
also shows how to check the signature on the sums file
(linuxmint-installation-guide.readthedocs.io, "Verify your ISO image").

## 2. Write it to the stick

Install **balenaEtcher** from etcher.balena.io. It runs on Windows, macOS
and Linux. Open it, choose **Flash from file** and pick the ISO, then
**Select target** and pick the USB stick (CONFIRM: the size should match
the stick, not an external drive). Then **Flash**. Etcher checks the
stick after writing. Wait for it to finish.

On Linux, without Etcher: find the stick with `lsblk -d -o NAME,SIZE,MODEL,TRAN`
(CONFIRM the `usb` one), then
`sudo dd if=linuxmint-*.iso of=/dev/sdX bs=4M status=progress conv=fsync`,
with `sdX` replaced by the stick. A wrong letter here erases a disk.

## 3. Boot the old computer from it

Plug the stick in, power on, and press the boot menu key straight away,
several times:

| Maker | Boot menu key |
|---|---|
| Dell | F12 |
| HP | Esc, then F9 |
| Lenovo | F12 (some IdeaPads: the small Novo button) |
| Acer | F12 (it may need *F12 Boot Menu* enabled in the firmware first) |
| ASUS | F8 on desktops, Esc on laptops |
| MSI | F11 |
| Gigabyte | F12 |
| Intel NUC | F10 |
| Intel Mac | Hold **Option** from power-on; pick the orange *EFI Boot* disk |

Pick the USB stick. In Mint's menu, choose the first entry, **Start Linux
Mint**. If the screen stays black (common with older NVIDIA cards), restart
and choose **Start Linux Mint (compatibility mode)**.

**If the stick isn't offered:** open the firmware settings instead (Dell F2,
HP F10, Lenovo F1 or F2, Acer F2, ASUS, MSI and Gigabyte Del) and check that
USB boot is allowed. If it is listed but won't start, switch **Secure Boot**
off for now. Write down what you change, so you can change it back.

The desktop appears after a minute or two. It runs from the stick, so it is
slower than an installed system. The user is `mint`, with no password.

## 4. Run the appraisal

Connect to the network (cable, or Wi-Fi from the panel), open **Terminal**,
and run:

```
lscpu
free -h
lsblk -o NAME,MODEL,SIZE,ROTA
sudo apt update && sudo apt install -y smartmontools
sudo smartctl -a /dev/sda
```

Repeat `smartctl` for each disk `lsblk` lists (`/dev/sdb`, `/dev/nvme0n1`,
and so on). Ignore the USB stick itself. Anything installed now lives in
memory and is gone at shutdown.

What to read, in the book's order (section 1.1):

1. **Memory:** `free -h`, the `total` column. 16 GB runs four or five
   services; 8 GB runs one or two.
2. **Disk:** `ROTA` 1 means a spinning disk, 0 an SSD. A spinning laptop
   drive will be the bottleneck. `smartctl` gives the health verdict, the
   power-on hours, and reallocated or pending sectors (non-zero is a warning).
3. **Network:** `ip -br link` shows the ports; `ethtool <port>` (after
   `sudo apt install -y ethtool`) shows their speed.
4. **Processor:** `lscpu` gives the model, cores and threads.

**Virtualization:** `grep -o -w -E 'vmx|svm' /proc/cpuinfo | sort -u`
should print `vmx` (Intel) or `svm` (AMD). If it prints nothing, the
setting may just be switched off. Restart into the firmware settings and
look for *Intel Virtualization Technology*, *VT-x* or *SVM Mode*. Enable it,
boot the stick again, and re-run the check. Linux hides the Intel flag while
the setting is off. Only a processor with no such setting can't run virtual
machines.

## 5. Optional: let the AI do it over SSH

In the live session's terminal:

```
sudo apt install -y openssh-server
passwd                       # set a password for the live user, mint
ip -4 -br addr               # note the address
```

From the computer your AI assistant runs on: `ssh mint@<address>`. Then the
assistant can run step 4 itself. The prompt from the book's *Try asking*
box works as it is.

## 6. Record it, and shut down

Save the results and the verdict as the machine's first wiki page (Chapter
2): model, memory, each disk with its type, health and hours, the network
ports, the virtualization result, and what runs out first. Then shut down
from the menu and remove the stick. The internal disk was never touched.
If you changed firmware settings in step 3, change them back now, unless
you're about to install Proxmox (1.2), which uses the same stick skills.
