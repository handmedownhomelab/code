# Playbook 3.5 — Your lab from anywhere, no open ports

> **For the reader.** Read this whole file before you give it to your AI
> assistant. You'll need a Tailscale account; several steps happen in its
> admin console, and only you can do those. Then say: *"Follow this
> playbook. Ask me before every step marked CONFIRM."*
>
> **For the AI assistant.** You are helping a reader of *Hand-Me-Down
> Homelab* build what section 3.5 describes. Follow the rules below for the
> whole session.

## Rules for the assistant

1. **Discover, don't assume.** Use the reader's networks and devices.
2. **Show each command before you run it**, and say which machine it runs on.
3. **CONFIRM** before installing Tailscale anywhere, and before advertising
   a route or an exit node.
4. **The admin console is the reader's.** Logging a device in, approving
   devices and routes, and editing access rules are things you describe;
   the reader clicks. Never ask for an auth key in the chat.
5. **Never port-forward** anything on the router as part of this. Zero
   open ports is the goal.
6. Don't publish tailnet names (`*.ts.net`) or `100.x` addresses tied to
   devices in anything public. They're fine in the reader's own wiki.

## Goal: what "done" looks like

- [ ] The reader's laptop, phone and the servers they SSH into are on the
      tailnet. From a phone on cellular, SSH and the home web pages work.
- [ ] One always-on node advertises the home network, and the route is
      **approved** in the admin console.
- [ ] Tailnet DNS uses the reader's Pi-hole, so `*.home.arpa` names work away
      from home.
- [ ] *Manually approve new devices* is on. Key expiry is disabled only for
      infrastructure nodes.
- [ ] The router has no ports forwarded.

## Discover first

| What | Why | How to find it |
|---|---|---|
| The home network ranges | The subnet route | The gateway's settings (book 1.4/1.5), e.g. `192.168.4.0/22` plus any IoT VLAN |
| The always-on node for the route | It must be up for remote LAN access to work | Ask; the book uses Home Assistant's Tailscale add-on |
| Whether any machine is a container | Containers need the tunnel device (step 2) | Ask |
| Pi-hole's address | Tailnet DNS | From playbook 3.1 |
| Current port forwards | To remove them | The gateway's settings |

## Steps

### 1. The reader's own devices

The reader installs the Tailscale app on their laptop and phone and logs in.
**Verify:** both appear under Machines in the admin console.

### 2. Servers — CONFIRM per machine

Install with Tailscale's Linux install script (download it to a file, show
it, run it), then `tailscale up` with a host name. It prints a **login
link**: give it to the reader to open and approve.

**In an unprivileged Proxmox container**, pass the tunnel device through
first: on Proxmox VE 9, `pct set <id> --dev0 /dev/net/tun`, then restart the
container. Without it, `tailscaled` can't create its interface.

**Verify:** `tailscale ip -4` prints a `100.x` address, and another tailnet
device can ping it.

### 3. The subnet router — CONFIRM

On the always-on node, advertise the home ranges
(`--advertise-routes=<range>,<range>`; on the Home Assistant add-on, its
`advertise_routes` option). Linux needs IP forwarding enabled (Tailscale's
docs give the two sysctl lines).

Then the **reader approves the route** in the admin console (Machines → the
node → Route settings). **Until then it does nothing.** In testing, an
advertised route showed in the node's preferences while the network got no
route at all, and the range was unreachable.

**Verify:** from a phone on cellular, with Tailscale on, a LAN address
answers (the gateway's page, or `ping` a server's LAN IP).

### 4. Tailnet DNS — the reader, in the admin console

DNS → add Pi-hole's LAN address as a nameserver (override local DNS). Keep
MagicDNS on. **Verify:** from the phone on cellular, a `*.home.arpa` name
opens.

### 5. Publishing one service to the tailnet only (optional)

For a service that should never be on the LAN (book 10.1's Nextcloud):
bind it to `127.0.0.1` and run `tailscale serve --bg --https=443
http://127.0.0.1:<port>`. HTTPS certificates must be enabled in the admin
console first.

**Verify:** from a tailnet device, `https://<machine>.<tailnet>.ts.net/`
answers with a valid certificate. The first request can take half a minute
while the certificate is issued (27 seconds in testing). From the LAN, the
service's port is refused.

### 6. Security settings — the reader, in the admin console

- **Device approval:** turn on *Manually approve new devices*.
- **Key expiry:** leave it on for laptops and phones. Disable it only for
  infrastructure that can't answer a login prompt (the subnet router, an
  exit node).
- **Access rules:** the default lets every device reach everything,
  including the whole LAN through the subnet router. Fine for one person.
  The moment anyone else joins, replace it, starting with exit-node use as
  internet only (`autogroup:internet`).

### 7. Close the old doors — CONFIRM

Remove any port forwards on the router. **Verify:** the router's settings
list none.

## Gotchas (from the book and the test)

- **An unapproved route does nothing**, and nothing tells you.
- **Re-check the routes after any update to the subnet-router node.** The
  book's war story is a route that silently emptied. The tell: the usual
  "Some peers are advertising routes but --accept-routes is false" warning
  on other Linux nodes disappears.
- **Remote LAN access depends on the subnet-router node being up.**
- **A DNS query from away arrives at Pi-hole from the subnet router**, so
  its log credits that node, not the device that asked.
- **On a Mac, use the Tailscale app.** In testing, a Mac running the
  open-source `tailscaled` daemon instead reached tailnet machines by
  address but couldn't resolve their `*.ts.net` names. Its system resolver
  never asked MagicDNS (100.100.100.100), which answered correctly.
- **tvOS suspends the Tailscale app**, so an Apple TV exit node can drop off
  silently. Opening the app brings it back.

## Rollback

`tailscale logout` on a node, then remove it in the admin console (a logged
out machine can linger there as expired). Disable or remove routes in the
console.
