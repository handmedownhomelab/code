# Playbook 6.2 — Ollama and Open WebUI

> **For the reader.** Read this whole file before you give it to your AI
> assistant. If you have an NVIDIA card, build the GPU box first (book 6.1;
> its playbook is marked Not tested). This one also runs on a CPU, slowly,
> with small models. Then say: *"Follow this playbook. Ask me before every
> step marked CONFIRM."*
>
> **For the AI assistant.** You are helping a reader of *Hand-Me-Down
> Homelab* build what section 6.2 describes. Follow the rules below for the
> whole session.

## Rules for the assistant

1. **Discover, don't assume.** The book's model and memory sizes are for a
   16 GB card. Size for the reader's hardware.
2. **Show each command before you run it**, and say which machine it runs on.
3. **CONFIRM** means stop, ask, and wait for a yes. Anything that installs
   software, opens a service to the network, or deletes anything is a
   CONFIRM step even if this file forgot to mark it.
4. **Get install steps from the upstream docs** (Ollama, Docker, Open
   WebUI). **Download install scripts to a file and show them** before
   running them; never pipe a script straight into a shell.
5. **Secrets:** the reader creates the Open WebUI admin account and enters
   any API keys (web search, for example) in its settings themselves.
6. **Verify by effect**: from another machine.
7. If the reader keeps a homelab wiki, record the model, its memory use,
   the settings and every program that calls Ollama.

## Goal: what "done" looks like

- [ ] Ollama runs as a service, listens on the network (firewalled to the
      machines that need it), and keeps one model loaded (`ollama ps`
      shows `Forever`).
- [ ] The model is already loaded after a reboot, before anyone asks.
- [ ] Open WebUI runs with login required, sign-up off, and an admin account
      that belongs to the reader.
- [ ] Open WebUI lists the model and a chat through it works.

## Discover first

| What | Why | How to find it |
|---|---|---|
| GPU and its memory | Decides the model size | `nvidia-smi`; none means CPU only |
| System memory and cores | The CPU-only case, and Docker's needs | `free -g`, `nproc` |
| Which machines will call Ollama | The firewall allows only them | Ask: Open WebUI, Home Assistant, scripts |
| The model to keep resident | One model, sized to fit with its context | Ask; measure with `ollama ps` after loading |
| Free disk | Models are gigabytes; Open WebUI's image is several | `df -h` |

## Steps

### 1. Install Ollama — CONFIRM

Download Ollama's Linux install script from its docs to a file, show it,
then run it. First install the two packages it relies on but doesn't
install itself:

- **`zstd`**: without it the installer stops with "This version requires
  zstd for extraction".
- **`pciutils`** (for `lspci`): without it the installer **can't detect an
  NVIDIA or AMD card** and says so in one warning line, which is easy to
  miss on a GPU machine.

**Verify:** `ollama --version` works, and the `ollama` service is active and
enabled. It listens on `127.0.0.1:11434` only, for now.

### 2. Settings for a shared server — CONFIRM

Put the book's settings in a systemd drop-in,
`/etc/systemd/system/ollama.service.d/override.conf` (`systemctl edit
ollama` opens the same file interactively): `OLLAMA_HOST=0.0.0.0:11434`,
`OLLAMA_CONTEXT_LENGTH` (the book uses 81920 on a 16 GB card; much less on
a CPU), `OLLAMA_FLASH_ATTENTION=1`, `OLLAMA_KV_CACHE_TYPE=q8_0`,
`OLLAMA_KEEP_ALIVE=-1`, `OLLAMA_NUM_PARALLEL=1`,
`OLLAMA_MAX_LOADED_MODELS=1`. The book explains each line. Reload systemd
and restart Ollama.

Then **firewall port 11434** to the machines from *Discover first*. Ollama
has no login of its own.

**Verify:** `ss -ltn` shows `*:11434`, and from another allowed machine
`curl http://<ollama-ip>:11434/api/version` answers.

### 3. The resident model — CONFIRM

`ollama pull <model>`, then send it one request. **Verify:** `ollama ps`
shows it with the expected context and `Forever` in the UNTIL column, and
its size fits the card with room to spare. Measure; don't trust the
"effective" size in a model's name.

### 4. Load it at boot

A small oneshot systemd unit, `ollama-preload.service`, after and requiring
`ollama.service`. It waits for `/api/version` to answer, then sends one
request for the model with `keep_alive: -1`. Enable it.

**Verify:** reboot the machine. Without anyone using it, `ollama ps` shows
the model loaded, `Forever`.

### 5. Docker and Open WebUI — CONFIRM

Install Docker Engine from Docker's repository (in a Proxmox container,
enable `nesting` and `keyctl`). Use Open WebUI's Docker Compose setup with
the book's settings: port 3000 → 8080, `OLLAMA_BASE_URL` pointing at the
host (`host.docker.internal` plus an `extra_hosts` entry for
`host-gateway`), **`WEBUI_AUTH=True`**, **`ENABLE_SIGNUP=False`**, a named
volume for its data, `restart: unless-stopped`. **Pin the image to a
release tag**, not `main`.

**Verify:** `http://<host>:3000/health` answers 200. The first start takes
a minute or so.

### 6. Claim the admin account now — the reader does this

**`ENABLE_SIGNUP=False` does not stop the first sign-up.** Until an account
exists, the first person to open Open WebUI and sign up becomes its
administrator. Only later sign-ups are refused. Ask the reader to open
`http://<host>:3000` straight away and create their account.

**Verify:** a second sign-up attempt is refused ("You do not have
permission").

### 7. Prove the whole path

Signed in as the reader: the model list shows the resident model, and a
chat gets an answer. **Verify** `ollama ps` still shows one model: Open
WebUI used the resident one rather than loading another.

### 8. Optional, from the book

Put Open WebUI behind the reverse proxy (playbook 3.3, **WebSockets on**).
Web search with an API key the reader enters. Model presets. Image
generation (6.3) and editing (6.5).

## Gotchas (from the book and the test)

- **Upgrading Ollama means re-running its installer.** The drop-in survives
  (tested), but the restart unloads the model and the preload unit only
  runs at boot. Run `systemctl start ollama-preload` after an upgrade.
- **Every caller shares one model slot.** A caller asking for a different
  model, or a different context size, makes Ollama reload: about three
  minutes for a 12 GB model. Book 6.7 is that story.
- **Size timeouts for a cold load**, not a warm answer.
- **"It's only on the LAN"** is why Open WebUI ran without login in the
  book's war story. Login on, sign-up off, and claim the account first.
- **Reasoning models can spend their whole output budget thinking.** Give
  them room, or pick one that doesn't think out loud.

## Rollback

`docker compose down` (add `-v` only if the reader wants Open WebUI's data
gone). Disable the preload unit and Ollama. Ollama's docs describe a full
uninstall, including its models folder.
