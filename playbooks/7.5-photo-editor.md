# Playbook 7.5 — Fix old photos by typing

> **For the reader.** Read this whole file, and `7.5/kontext_edit_api.json`,
> before you give them to your AI assistant. You need ComfyUI from playbook
> 7.4, Open WebUI and Ollama from playbook 7.2, and about 18 GB of free disk.
> It is **Not tested** (see the header). Then say: *"Follow this playbook. Ask
> me before every step marked CONFIRM."*
>
> **For the AI assistant.** You are helping a reader of *Hand-Me-Down Homelab*
> build what section 7.5 describes. Follow the rules below for the whole
> session.

## Rules for the assistant

1. **Discover, don't assume.** Node names, Open WebUI's settings and model
   filenames change between releases. Check the installed versions.
2. **Show each command before you run it**, and say which machine it runs on.
3. **CONFIRM** means stop, ask, and wait for a yes. Anything that downloads
   gigabytes, stops another program's model, changes Open WebUI's settings or
   deletes anything is a CONFIRM step even if this file forgot to mark it.
4. **Test on a generated image, never on a family photo.** The reader decides
   what real photos go through it, later.
5. **Never set a global task model in Open WebUI on a one-slot Ollama** (see
   Gotchas). Never print a key from a settings page.
6. **Verify by effect**: a new file in ComfyUI's output folder, not a friendly
   sentence in the chat.
7. If the reader keeps a homelab wiki, record the model files, the workflow's
   node mappings, the preset's settings and the rollback copy of the settings.

## Goal: what "done" looks like

- [ ] The four Kontext model files are in ComfyUI's folders, with their byte
      counts checked.
- [ ] The workflow restores a synthetic damaged image when run directly on
      ComfyUI, with its composition intact.
- [ ] Open WebUI's Image Edit points at ComfyUI, with the workflow and its node
      mappings.
- [ ] A "Photo Editor" model preset edits a photo from the chat, twice in a row,
      and the reply runs fully on the GPU.

## Discover first

| What | Why | How to find it |
|---|---|---|
| ComfyUI's launcher has `--disable-smart-memory` | Without it, the second edit can fail (see Gotchas) | Read `comfyui-run.sh` (playbook 7.4) |
| RAM and card memory | ComfyUI used 23 GB of RAM with the larger text encoder | `free -g`; `nvidia-smi` |
| Open WebUI's version | Setting names move | Its admin panel, or the image tag |
| A vision model in Ollama that fits beside the card's other work | The reply model has to accept the photo | `ollama list`; the book used `qwen3-vl:8b` (6.1 GB on disk) |
| Who else uses Ollama | The reply model takes the one model slot | Book 7.2 and 7.7 |

## Steps

### 1. The model files — CONFIRM (about 18 GB)

Into ComfyUI's model folders, from Comfy-Org's or the model authors' repositories
on Hugging Face:

| File | Folder | About |
|---|---|---|
| `flux1-dev-kontext_fp8_scaled.safetensors` | `models/diffusion_models/` | 11.9 GB |
| `clip_l.safetensors` | `models/text_encoders/` | 246 MB |
| `t5xxl_fp8_e4m3fn_scaled.safetensors` | `models/text_encoders/` | 5.2 GB |
| `ae.safetensors` | `models/vae/` | 335 MB |

Use the fp8 T5 encoder: the fp16 one nearly doubles it, and took ComfyUI to 23 GB
of RAM on the author's box. Read FLUX.1 Kontext [dev]'s license before you use
its output in anything you sell.

**Verify:** each file's byte count matches the size the repository lists.

### 2. Test the workflow outside the chat — CONFIRM (stops the chat model)

`7.5/kontext_edit_api.json` is an API-format graph: load the image, encode the
instruction, the Kontext model, `FluxGuidance` at 2.5, sample at denoise 1.0, save.

Start ComfyUI with its launcher. Have a script make a synthetic damaged image
from a generated picture: scratches, dust, grain, a sepia fade. Upload it with
`POST /upload/image`, set node `50`'s `image` and node `6`'s `text` ("remove the
scratches and dust, fix the faded colors"), and `POST /prompt`.

**Verify:** a new file appears in `ComfyUI/output/`. Look at it: the damage is
gone and the composition has not moved. If a node name is refused, compare it with
the installed version's own Kontext template rather than guessing.

### 3. Point Open WebUI's Image Edit at it — CONFIRM

First save the current settings, for rollback (`GET /api/v1/images/config` with an
admin token; don't print the token). Then, under Admin → Settings → Images:

- Edit engine: ComfyUI, with the ComfyUI address as Open WebUI's container reaches it.
- Edit model: `flux1-dev-kontext_fp8_scaled.safetensors`.
- Workflow: the contents of `7.5/kontext_edit_api.json`.
- Node mappings: prompt → node `6` `text`; image → node `50` `image`; seed → node
  `31` `seed`; model → node `37` `unet_name`.

**Verify:** `POST /api/v1/images/edit` with the damaged image returns a restored
image, and `ComfyUI/output/` has a new file. ComfyUI must be running; Open WebUI
can't start it.

### 4. The Photo Editor preset — CONFIRM

Under Workspace → Models, a new model on the vision model:

| Setting | Value | Why |
|---|---|---|
| Function calling | `legacy` | In `native` mode the editor is never called |
| Keep alive | `0` | Hands the slot back right after the reply |
| Context (`num_ctx`) | `8192` | A global 80K context pushed the reply model onto the CPU |
| Capabilities | Vision and image generation on | The photo stays in the messages |
| Default features | Image generation | So the chat doesn't need a toggle each time |
| System prompt | "The image editor has already applied the instruction. Reply with one short sentence confirming it, or relay the error. Do not describe the photo." | Keeps the reply short |

**Verify:** pick the preset in a new chat, attach the damaged image, type the
instruction. A new file appears in `ComfyUI/output/`, then a one-line reply. Do it
**twice in a row**: the second edit is the real test. `ollama ps` during the reply
shows the model on the GPU, and `free -g` shows RAM to spare.

## Gotchas (from the book and the author's machine)

- **Chat models can't edit photos.** They can look at one. No Ollama model does
  this job.
- **The second edit fails and the first looks fine.** If ComfyUI holds its VRAM,
  the reply model lands in system RAM, and the kernel can kill ComfyUI. The next
  edit finds nothing to talk to. `--disable-smart-memory`, the fp8 encoder and the
  small context fix it. Check `journalctl -k | grep -i oom`.
- **A global task model jams a one-slot server.** A small helper for titles and tags
  evicts the main model on every chat, and everything else waits for a reload. Leave
  it empty.
- **Forge and ComfyUI can't both run** on one card, so Image Edit only works while
  ComfyUI is up.
- **Kontext invents detail where there is none.** Fine for fun, not for a family
  record. Compare with the original before you keep a restoration.

## Rollback

POST the saved settings back to `/api/v1/images/config/update`, delete the preset,
and remove the Kontext diffusion model. Keep `clip_l`, `ae` and the encoder if
anything else uses them.
