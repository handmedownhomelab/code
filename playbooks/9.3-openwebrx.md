# Playbook 9.3 — OpenWebRX+

> **For the reader.** Read this whole file before you give it to your AI
> assistant. You need a Raspberry Pi (a Zero 2 W is enough; bigger is
> fine), a microSD card of 16 GB or more, an RTL-SDR dongle (the book's is
> an RTL-SDR Blog V3), an antenna (the book's is the RTL-SDR Blog dipole
> kit), and a computer that can write SD cards. This playbook is **Not
> tested** (see the header). Then say: *"Follow this playbook. Ask me before
> every step marked CONFIRM."*
>
> **For the AI assistant.** You are helping a reader of *Hand-Me-Down
> Homelab* build what section 9.3 describes. Follow the rules below for the
> whole session.

## Rules for the assistant

1. **Discover, don't assume.** The reader's dongle, antenna and local
   stations decide the profiles. Find real signals near *them*.
2. **Show each command before you run it**, and say which machine it runs
   on: the Pi or the reader's computer.
3. **CONFIRM** means stop, ask, and wait for a yes. Writing an SD card,
   installing software, changing the receiver's settings file, or deleting
   anything is a CONFIRM step even if this file forgot to mark it.
4. **Get install steps from the projects' own pages** (the image's
   releases, the OpenWebRX+ README); they change. Don't pipe downloaded
   scripts into a shell.
5. **Secrets:** the reader types the Pi's password and the receiver's admin
   password themselves.
6. **What may be listened to is the reader's to check** for where they
   live. Broadcast, weather, air-traffic voice and aircraft beacons are
   generally fine; recording or sharing private communications is not.
   This isn't legal advice, and you shouldn't give any.
7. **Verify by effect**: a station heard, a weather broadcast decoded, an
   aircraft on the map.
8. If the reader keeps a homelab wiki, record the hardware, the image or
   package version, the profiles with their gains, and the antenna lengths.

## Goal: what "done" looks like

- [ ] The Pi has its own name, a reserved address, key-only SSH and the
      reader's own account.
- [ ] OpenWebRX+ answers in a browser on the LAN, with an admin login that
      belongs to the reader, and is not reachable from the internet.
- [ ] The receiver's location is set to the nearest town, not the house.
- [ ] Profiles for the reader's bands, each with a gain that doesn't clip,
      and each proved with a real signal.
- [ ] The dongle's frequency correction (`ppm`) is right for *that* dongle:
      measured, not guessed.

## Discover first

| What | Why | How to find it |
|---|---|---|
| The dongle | Range, gain steps, direct sampling for HF, a TCXO or not | Its packaging; on the Pi, `lsusb`, and `rtl_test` with the receiver stopped (it prints the tuner and its gain steps; Ctrl-C) |
| The antenna | Element lengths decide which bands work | The kit's sheet; each leg ≈ 7500 / frequency in MHz, in cm |
| Local signals to prove each profile | You can't tell "no signal" from "broken" without a known one | Strong FM stations; the nearest NOAA Weather Radio channel (US); the nearest airport's ATIS frequency (a continuous loop); amateur repeaters |
| Pi model, and Wi-Fi or wired | The image differs by model; the Zero has Wi-Fi only | The board |
| The network for it | A receiver needs nothing else on the LAN; an IoT network is a fine home | Ask; the router |
| The nearest town's coordinates | The receiver shows its location on its map | Ask |

## Steps

### 1. Write the image — CONFIRM (erases the card)

The author used the **OpenWebRX+ Raspberry Pi image**: Raspberry Pi OS
with OpenWebRX+, the RTL-SDR Blog driver, nginx and a cache already set up
(it is built with `0xAF/openwebrxplus-rpi-builder`). Download it from the
**Releases page of `luarvique/openwebrx`**, the one the project's README
links, choosing the build for the reader's Pi. The author's is the 32-bit
1.2.102 image of 2025-12-19; the newest (1.2.117) is 64-bit only, which a
Zero 2 W can run, though its 512 MB is tighter under 64-bit. Check the
checksum where the release lists one, and write it with Raspberry Pi
Imager, setting its customisation options: a hostname, the reader's own
user (not `pi`), Wi-Fi, and SSH with the reader's public key.

On a Pi that already runs Raspberry Pi OS, the alternative is the
OpenWebRX+ package repository (`luarvique.github.io/ppa`, per the
README) and the `openwebrx` package; nginx in front is then the reader's
to add (step 3 shows the shape).

**Verify:** the Pi boots, `ssh <user>@<pi>` works by key, and
`dpkg -l openwebrx` shows the package.

### 2. Make the Pi an ordinary managed host — CONFIRM

- A **DHCP reservation** on the router for the Pi's MAC address, and a
  local DNS name (book 6.1).
- **Key-only SSH:** `PasswordAuthentication no` in a drop-in under
  `/etc/ssh/sshd_config.d/`; check with `sshd -t`; test a new key login
  before closing the old session.
- If the image created a default `pi` account, lock it or delete it.
- `apt update && apt full-upgrade` once (the receiver's packages come from
  its own repository and update the same way).

**Verify:** the Pi gets the same address after a reboot; a password login
is refused.

### 3. The web front and the admin account

The image serves OpenWebRX+ on port **8073**, and on 80/443 through
**nginx → Varnish (127.0.0.1:6081) → the receiver**. nginx's site passes
WebSocket upgrades (`Upgrade` and `Connection` headers), which the
waterfall and audio need, and uses the self-signed "snakeoil" certificate.
If the reader runs a reverse proxy (book 6.3), point it at port 80 and turn
WebSockets on there too.

Create the admin account (the reader types the password):

```
sudo openwebrx admin adduser <name>
```

**Verify:** `http://<pi-name>/` shows the waterfall; `http://<pi-name>/settings`
asks for the login and accepts the reader's. From outside the house
(phone off Wi-Fi), nothing answers: no port forward, no public listing.

### 4. Location and general settings

In Settings → General: a receiver name that doesn't name the household,
and the **location of the nearest town**, rounded (two decimal places is
about a kilometre). The map is centred on it.

**Verify:** the map's centre is the town, not the street.

### 5. Antenna lengths

A vertical dipole, each leg about **7500 / f(MHz) cm**:

| Band | Frequency | Each leg |
|---|---|---|
| FM broadcast | 98 MHz | 76 cm |
| Airband | 120 MHz | 62 cm |
| NOAA Weather Radio | 162.5 MHz | 46 cm |
| 2 m amateur | 145 MHz | 52 cm |
| 70 cm amateur | 439 MHz | 17 cm |
| ADS-B | 1090 MHz | 7 cm |

Vertical is right for all of these (it's how they are transmitted), and a
vertical dipole doesn't need pointing. A kit's two element pairs may not
cover every length (the book's: 70 cm falls between them, so use the long
pair at its shortest).

### 6. Profiles, one at a time, each proved — CONFIRM each change

Settings → SDR devices → the dongle → profiles. The book's set, as a
starting point:

| Profile | Mode | Centre / tuned | Sample rate | Gain |
|---|---|---|---|---|
| FM broadcast | WFM | a local station | 2.048 Msps | 23–30 dB |
| Airband, tower | AM | centre 121.0, tuned to the tower | 2.048 Msps | 40 |
| Airband, ATIS | AM | centre near the ATIS frequency | 2.048 Msps | 40 |
| NOAA Weather Radio | NFM | centre 162.25, tuned to the local channel | 2.048 Msps | 30 |
| 2 m, 70 cm, 10 m | NFM / as used | the band | 2.048 Msps | ~29 |
| ADS-B 1090 | ADS-B | 1090 MHz | 2.4 Msps (fixed by OpenWebRX) | 49.6 |

Rules that came from the author's receiver:

- **Keep the centre off the frequency you listen to.** The dongle has a
  spike at its exact centre; offset it (121.0 for a 120.1 tower).
- **2.048 Msps.** Higher rates drop samples on a small Pi. ADS-B is the
  exception (OpenWebRX fixes it at 2.4 Msps); check it with the receiver
  running for a while and no errors in the log.
- **Steps of 25 kHz** for airband and weather; 12.5 kHz where channels are
  narrower.

**Verify each profile with a known signal:** an FM station clearly; the
weather broadcast (it runs all day); the ATIS loop (airband is silent
between transmissions, so ATIS is the test); for ADS-B, aircraft on the map
within a few minutes, with the short elements fitted.

### 7. Gain: lower than you think

The book's dongle **clips at its maximum gain on the FM band**, which
flattens the whole display and looks exactly like a dead antenna. Start
around 25 dB on VHF; raise it only while the waterfall's noise floor rises
and strong signals don't smear. ADS-B is weak and can take maximum gain.

**Verify:** on each profile, the strongest signal stands out of the noise
and the noise between signals is darker than the signals.

### 8. Frequency correction (`ppm`): measure, don't guess

A V3 with a TCXO is within about 1 ppm and should have **`ppm` unset**. A
plain crystal can be tens of ppm off, enough to miss narrow channels on
70 cm. Measure against a reference more precise than the claim:

- **US digital TV (ATSC):** each station transmits a pilot tone at the
  channel's lower edge **+ 309.441 kHz**. Record a few seconds with
  `rtl_sdr` with the pilot at several different offsets in the window, find
  its frequency (an FFT in Python is enough), and compare the average to
  the true one. The book's dongle was 26 Hz off at 174.309441 MHz,
  −0.15 ppm.
- Elsewhere, any transmitter with a published, stable frequency (a
  broadcast carrier, a time-signal station) will do.

Stop OpenWebRX+ while `rtl_sdr` uses the dongle, and start it afterwards.

**Verify:** set `ppm` only if the error is several ppm, then repeat the
measurement; the error should be near zero.

## Gotchas (from the book and the author's receiver)

- **`rtl_test -p` measures the Pi, not the dongle.** It compares the
  dongle's clock to the Pi's, and a Pi has no real-time clock. On the
  author's Pi it reported −27 ppm on a dongle that is −0.15 ppm, and nearly
  led to a "correction" that would have put 70 cm 11.8 kHz off.
- **`rtl_power` couldn't tell antenna from no antenna** on the author's Pi.
  Compare short `rtl_sdr` captures on a station and between stations
  instead.
- **Maximum gain looks like a broken antenna** (step 7).
- **ADS-B needs the short elements, not more gain.** With FM-length legs,
  the author's receiver decoded nothing in 45 seconds.
- **HF needs an HF antenna.** A V3 can tune below 24 MHz (direct sampling),
  but a VHF dipole picks up next to nothing there; silence is the antenna,
  not the dongle.
- **Not in a hot attic.** A Pi Zero idles about 26 °C above room
  temperature and throttles at 80 °C. If the antenna goes up, keep the Pi
  below and extend USB, not the thin coax (about 3 dB lost at 1090 MHz over
  3 m).
- **Solar inverters and optimizers are broadband noise.** Measure the
  noise floor with the panels producing and off before choosing an antenna
  spot near them.
- **A counterfeit dongle can look identical.** Buy from the maker's own
  store, and let step 8 settle it.
- **Background services are off by default** (`services_enabled`), so the
  ADS-B decoder only runs while someone has that profile open.

## Rollback

Settings changes: the image keeps its state in `/var/lib/openwebrx/`; back
up `settings.json` before editing by hand, and restore it with the service
stopped. The whole receiver: reflash the card, and remove the DHCP
reservation and DNS name.
