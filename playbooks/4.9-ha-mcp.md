# Playbook 4.9 — Claude and Home Assistant through MCP

> **For the reader.** Read this whole file before you give it to your AI
> assistant. You create the Home Assistant token yourself (step 1). Then
> say: *"Follow this playbook. Ask me before every step marked CONFIRM."*
>
> **For the AI assistant.** You are helping a reader of *Hand-Me-Down
> Homelab* build what section 4.9 describes. Follow the rules below for the
> whole session.

## Rules for the assistant

1. **The token is the reader's.** They create it and put it into the client
   configuration themselves. Never ask for it in the chat, never print it,
   never write it into a file other than the client's own config.
2. **Start read-only** (step 3), and stay read-only until the reader says
   otherwise.
3. **CONFIRM** before any write to Home Assistant, every time, showing the
   change first.
4. **Every write follows the write loop** (step 5): fresh read, change,
   write with the hash, read back.

## Goal: what "done" looks like

- [ ] A long-lived token just for this client, with a name that says so.
- [ ] ha-mcp configured in Claude Code with that token and the reader's Home
      Assistant URL, readable only by the reader.
- [ ] A read-only session answers real questions about the house.
- [ ] The reader has decided, deliberately, when to turn writes on.

## Discover first

| What | Why | How to find it |
|---|---|---|
| Home Assistant's URL | Through the proxy, e.g. `https://ha.home.arpa` | From playbooks 3.3 and 4.1 |
| Whether this machine trusts the CA | HTTPS to the proxy | `curl -s -o /dev/null -w '%{ssl_verify_result}' <url>` prints `0` |
| `uv` / `uvx` | How ha-mcp is usually run | `command -v uvx`; install uv from its docs if missing |

## Steps

### 1. A token for this client — the reader does this

In Home Assistant: your profile → **Security** → **Long-lived access
tokens** → Create, named for the client (e.g. "claude-code-laptop"). One
per client, so one can be revoked without breaking the others. The reader
keeps it on the clipboard for step 2.

### 2. Add the server to Claude Code — CONFIRM

Following ha-mcp's README for Claude Code: a stdio server run by `uvx
ha-mcp@latest`, with the environment variables `HOMEASSISTANT_URL` and
`HOMEASSISTANT_TOKEN`, **plus `READ_ONLY_MODE=true`** for now. Give the
reader the exact `claude mcp add` command with a placeholder where the token
goes; they paste the real token when they run it, so it never passes
through you.

**Verify:** a new Claude Code session lists the server as connected. The
config file holding the token (`~/.claude.json` for a user-scope server)
is readable only by the reader.

### 3. Prove read-only

- Ask a read question: "evaluate the template `{{ states | count }}`", or
  "what's unavailable right now?" It answers with real numbers.
- With Read Only Mode on, the tool list is about half its normal size (40
  of 77 in testing). A write tool is either absent or refused with a
  `READ_ONLY_MODE` error.

### 4. The questions to start with

From the book: what's unavailable and since when; which automations haven't
triggered in 30 days; read a trace and say why an automation didn't run.

### 5. Turning writes on — CONFIRM, the reader decides

Set `READ_ONLY_MODE` to false (or remove it) and restart the session. From
then on, every change follows the loop:
1. Read the current configuration **fresh**, with its hash.
2. Make the change and show it to the reader.
3. Write it with the hash. If anything changed in between, the write fails
   on purpose.
4. **Read it back** and check the change is there. Don't trust "success".

## Gotchas (from the book and the test)

- **77 tools, 43 of them able to change things.** "Start read-only" is a
  setting, not just a habit: `READ_ONLY_MODE=true`.
- **The `ha_manage_*` tools stay listed in Read Only Mode**: they mix
  read and write operations, and the write ones are blocked when called.
- **`@latest` updates the server at every start.** Pin a version if you'd
  rather update deliberately.
- **Device triggers break on re-pairing** (new device ID). The book's
  exchange swaps them for event triggers keyed on the device's address.
- **Assist's Extended OpenAI Conversation bridge doesn't trust the system's
  certificate store**, and can break on Home Assistant updates (book 4.9's
  warning box).

## Rollback

`claude mcp remove` the server, and delete its token in Home Assistant's
profile → Security.
