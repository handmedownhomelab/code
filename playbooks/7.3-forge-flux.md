# Playbook 7.3 — Forge and FLUX

> **For the reader.** Read this whole file, and the files in `7.3/`, before
> you give them to your AI assistant. You need the GPU box from book 7.1
> (`nvidia-smi` working), about 30 GB of free disk, SSH from your
> workstation to the GPU box by key, and Claude Code on the workstation. If
> Ollama runs on the same card (7.2), this playbook makes the two take
> turns. It is **Not tested** (see the header). Then say: *"Follow this
> playbook. Ask me before every step marked CONFIRM."*
>
> **For the AI assistant.** You are helping a reader of *Hand-Me-Down
> Homelab* build what section 7.3 describes. Follow the rules below for the
> whole session.

## Rules for the assistant

1. **Discover, don't assume.** The book's card has 16 GB and a chat model
   that fills 14 GB of it. Measure the reader's card and what's on it.
2. **Show each command before you run it**, and say which machine it runs
   on: the GPU box or the workstation.
3. **CONFIRM** means stop, ask, and wait for a yes. Anything that installs
   software, downloads gigabytes, stops another program's model, or deletes
   anything is a CONFIRM step even if this file forgot to mark it.
4. **Get install steps from Forge Neo's README** on the `neo` branch; they
   change. Don't pipe downloaded scripts into a shell.
5. **Don't open port 7860 in the firewall.** Forge has no login. It is
   reached through an SSH tunnel only.
6. **Verify by effect**: an image you have opened and looked at.
7. If the reader keeps a homelab wiki, record the install path, the model
   file and where it came from, the launcher, and every program the
   launcher stops.

## Goal: what "done" looks like

- [ ] Forge Neo installed on the GPU box, with the FLUX checkpoint loaded by
      default and FLUX's settings as the defaults.
- [ ] Forge is only ever started by `forge-run.sh`, which unloads every
      Ollama model and stops the other GPU apps first.
- [ ] `forge` on the workstation opens a tunnel, starts Forge, opens the
      browser; Ctrl-C stops Forge and loads the chat model back.
- [ ] Port 7860 does not answer from the LAN.
- [ ] The `forge-image` Claude Code skill generates an image, opens it, and
      critiques it.

## Discover first

| What | Why | How to find it |
|---|---|---|
| Card memory, and what's using it | FLUX fp8 needs about 11 GB while it runs | `nvidia-smi`; `ollama ps` if Ollama is installed |
| Other GPU apps on the box, and how each is started | The launcher must stop them | Ask; `nvidia-smi` lists the processes using the card |
| The chat model to load back afterwards, and who calls it | Those callers pay a cold load if it isn't reloaded | `ollama ps`; book 7.7 |
| Free disk | 17 GB model, about 6 GB of Python environment, and outputs | `df -h ~` |
| An existing FLUX checkpoint (ComfyUI, 7.4) | Keep one copy and link it | `find ~ -name 'flux1-dev*.safetensors'` |
| The workstation's shell, and its SSH name for the GPU box | `forge.zsh` is for zsh; the scripts need the host | `echo $SHELL`; `ssh <host> true` |

## Steps

### 1. Install Forge Neo — CONFIRM

On the GPU box, as the reader's user (not root):

```
git clone --branch neo https://github.com/Haoming02/sd-webui-forge-classic ~/sd-webui-forge-neo
```

Forge Neo uses **uv** for its Python environment; install uv for the user
as the README says (it lands in `~/.local/bin`). In `webui-user.sh` set:

```
export COMMANDLINE_ARGS="--uv --listen --port 7860 --api"
```

`--listen` makes Forge answer on the machine's addresses, so the tunnel can
reach it; ufw (7.1) keeps the LAN out. `--api` is what the skill uses.

**Verify:** `git -C ~/sd-webui-forge-neo branch --show-current` says `neo`.

### 2. The model — CONFIRM (17 GB download)

The book uses the single-file 8-bit FLUX.1 [dev] checkpoint,
`flux1-dev-fp8.safetensors`, which bundles the text encoders and VAE. It is
in Hugging Face's `Comfy-Org/flux1-dev` repository, which needs no login.
**The model's license still applies:** read FLUX.1 [dev]'s license on Black
Forest Labs' model page with the reader, and record which model made which
image.

Put it in `models/Stable-diffusion/`. If ComfyUI (7.4) already has it,
**symlink** the existing file instead of downloading it twice.

**Verify:** `ls -lL` shows about 17.2 GB, and the checksum matches the one
on the file's Hugging Face page.

### 3. The launcher — CONFIRM

Copy `7.3/forge-run.sh` to `~/forge-run.sh` on the GPU box and make it
executable. Set `CHAT_MODEL` and the `OTHER_GPU_APPS` patterns from
*Discover first*; delete the ones the reader doesn't run. It unloads
**every** Ollama model, not just the chat model: with `KEEP_ALIVE=-1`,
whatever ran last stays pinned in memory.

**Verify:** `bash -n ~/forge-run.sh` passes, and each `OTHER_GPU_APPS`
pattern matches that app's process when it is running
(`pgrep -af '<pattern>'`) and nothing else.

### 4. First launch — CONFIRM (stops the chat model)

Run `~/forge-run.sh` in a terminal on the GPU box. The first launch builds
the Python environment and installs a PyTorch build for the card; on a new
card generation (Blackwell), check it chose a CUDA build the driver
supports (the book's: `2.11.0+cu130` on CUDA 13.0). It can take a long
while. The first image after that also pays a one-time CUDA compile (about
90 s on Blackwell).

**Verify:** the log shows the model loaded and the API up, and on the GPU
box `curl -s localhost:7860/sdapi/v1/sd-models` lists `flux1-dev-fp8`.
`nvidia-smi` shows no Ollama model alongside it.

### 5. FLUX's settings as the defaults

In Forge's UI, select the FLUX checkpoint and its `flux` preset; both are
kept in `config.json`. Set the txt2img and img2img defaults that work for
FLUX: **CFG 1**, **Distilled CFG 3.5**, sampler **Euler**, scheduler
**Simple**, 20 steps, 1024 × 1024 (img2img denoise 0.6), and save them as
the UI defaults (`ui-config.json`; back it up first).

**Verify:** stop and restart Forge; a new tab opens with those values and
the FLUX checkpoint. One 1024 × 1024 image at 20 steps takes well under a
minute on a 16 GB card once the model is loaded (the book's: about 36 s).

### 6. The tunnel from the workstation

Stop Forge (Ctrl-C). On the workstation, source `7.3/forge.zsh` from
`~/.zshrc` with `GPU_HOST` and `CHAT_MODEL` set. Bash users: the function
ports with small changes (the `{1..90}` loop and the trap work the same).

**Verify:**
- `forge` opens Forge in the browser at `http://localhost:7860`.
- From another LAN machine, `curl -m5 http://<gpu-box>:7860/` gets no
  answer (ufw drops it).
- Ctrl-C ends it, and on the GPU box no Forge process is left
  (`pgrep -af 'sd-webui-forge-neo/venv/bin/[p]ython'` prints nothing),
  `nvidia-smi` shows the memory freed, and `ollama ps` shows the chat model
  again within a few minutes.

### 7. The AI skill

Copy `7.3/forge-image/` to `~/.claude/skills/forge-image/` (or your
assistant's skills folder—`~/.gemini/skills/`, `~/.agents/skills/`—see book
2.3) on the
workstation. Set `GPU_HOST` in `ensure_forge.sh` and the output folder in
`SKILL.md`. Make both scripts executable.

**Verify:** with Forge stopped, ask Claude Code for an image ("generate a
flat logo of a lighthouse, no text"). It runs `ensure_forge.sh`, which
starts Forge through the tunnel; it generates, **opens the PNG and says
what's wrong with it**, and offers a next step. The preflight's tunnel runs
in the background with no terminal, so killing it may leave Forge running:
stop Forge on the GPU box (`pkill -f 'sd-webui-forge-neo/venv/bin/[p]ython'`),
then load the chat model back, and check both with `nvidia-smi` and
`ollama ps`.

## Gotchas (from the book and the author's machine)

- **Nothing gives the card back by itself.** Forge, ComfyUI and ACE-Step all
  keep their memory until stopped. A Forge left running starves the chat
  model, and everything that calls it falls back to the CPU or times out.
  Stop it when you're done. (The author's machine also runs a small idle
  watchdog that stops Forge after 20 minutes without a generation; book 7.7
  is the wider story.)
- **The skill's preflight starts Forge but doesn't stop it.** Stopping is the
  reader's job, or a watchdog's.
- **Use `-tt`, not `-t`.** Launched from something without a terminal (an
  AI session, a script), `-t` gives the remote side no terminal, so quitting
  doesn't hang it up and Forge keeps running. `forge.zsh` uses `-tt` plus a
  trap that kills it directly.
- **FLUX ignores the negative prompt.** Say what you don't want in the
  prompt itself: *"plain unbranded … no text, no letters, no logos."* The
  book's first logo had an Apple logo on it.
- **"Smaller" chat models may not make room.** A model with "e2b" or "e4b"
  ("effective" size) in its name can take nearly as much memory as the full
  one. Measure with `nvidia-smi`, don't trust the name.
- **Look where it will be shown.** A logo in a circle at 48 pixels, a banner
  cropped for TVs and phones. The skill can make preview sheets; ask for one.
- **Updating Forge** (`git pull` on `neo`) refreshes its packages on the next
  launch. It kept the book's local `webui-user.sh` settings and PyTorch
  build, but check `--uv --listen --port 7860 --api` is still there after a
  pull, and generate one image.

## Rollback

Stop Forge. Remove `~/sd-webui-forge-neo` (check the model in
`models/Stable-diffusion/` is a symlink before deleting, if ComfyUI uses
the file), `~/forge-run.sh`, the `forge.zsh` line in `~/.zshrc`, and
`~/.claude/skills/forge-image/`. Nothing was opened in the firewall.
