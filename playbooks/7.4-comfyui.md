# Playbook 7.4 — ComfyUI for video

> **For the reader.** Read this whole file, and the files in `7.4/`, before
> you give them to your AI assistant. You need the GPU box from book 7.1,
> about 60 GB of free disk for the two video models, SSH from your
> workstation to the GPU box by key, `ffmpeg` on the workstation, and Claude
> Code there. If you built 7.3, this one takes turns with Forge on the same
> card. It is **Not tested** (see the header). Then say: *"Follow this
> playbook. Ask me before every step marked CONFIRM."*
>
> **For the AI assistant.** You are helping a reader of *Hand-Me-Down
> Homelab* build what section 7.4 describes. Follow the rules below for the
> whole session.

## Rules for the assistant

1. **Discover, don't assume.** The book's card has 16 GB. Model choice,
   clip length and resolution depend on the reader's card.
2. **Show each command before you run it**, and say which machine it runs
   on: the GPU box or the workstation.
3. **CONFIRM** means stop, ask, and wait for a yes. Anything that installs
   software, downloads gigabytes, stops another program's model, or deletes
   anything is a CONFIRM step even if this file forgot to mark it.
4. **Get install steps from ComfyUI's own README** (the manual install for
   NVIDIA); they change. Don't pipe downloaded scripts into a shell.
5. **Don't open port 8188 in the firewall.** ComfyUI has no login. It is
   reached through an SSH tunnel only.
6. **Verify by effect**: a clip you have pulled frames from and looked at.
7. If the reader keeps a homelab wiki, record the install path, the
   PyTorch build, every model file and where it came from, the launcher,
   and every program the launcher stops.

## Goal: what "done" looks like

- [ ] ComfyUI runs from its own venv on the GPU box with a PyTorch build
      for the card, and gives its VRAM back after each job.
- [ ] It is only ever started by `comfyui-run.sh`, which unloads every
      Ollama model and stops the other GPU apps first.
- [ ] `comfy` on the workstation opens a tunnel, starts ComfyUI, opens the
      browser; Ctrl-C stops it and loads the chat model back.
- [ ] Port 8188 does not answer from the LAN.
- [ ] Wan 2.2 and LTX-Video each render a text-to-video and an
      image-to-video clip through the `comfyui-video` skill, which looks at
      frames and critiques them.

## Discover first

| What | Why | How to find it |
|---|---|---|
| Card memory, and what's using it | Wan 5B uses about 10 GB while it runs | `nvidia-smi`; `ollama ps` |
| The CUDA version the driver supports | Decides the PyTorch build (cu128, cu130…) | `nvidia-smi` header |
| Other GPU apps, and how each is started | The launcher must stop them | Ask; `nvidia-smi` process list |
| The chat model to load back, and its callers | They pay a cold load otherwise | `ollama ps`; book 7.7 |
| Free disk | Wan files about 18 GB, LTX about 16 GB, venv about 6 GB, plus outputs | `df -h ~` |
| Python 3 with `venv` on the GPU box | ComfyUI gets its own environment | `python3 --version`; `python3 -m venv --help` |
| An existing FLUX checkpoint (7.3) | One copy, linked | `find ~ -name 'flux1-dev*.safetensors'` |

## Steps

### 1. Install ComfyUI — CONFIRM

On the GPU box, as the reader's user:

```
git clone https://github.com/comfyanonymous/ComfyUI ~/ComfyUI
python3 -m venv ~/ComfyUI/venv
```

Into that venv, install PyTorch **first**, from PyTorch's own index for the
CUDA version in *Discover first* (the book's: `torch==2.11.0+cu130` from
`download.pytorch.org/whl/cu130`), then `pip install -r requirements.txt`.

**Verify:**
`~/ComfyUI/venv/bin/python -c 'import torch; print(torch.__version__, torch.cuda.is_available(), torch.cuda.get_device_name(0))'`
prints the build you chose, `True` and the card's name. On a new card
generation, also check the card's architecture is in
`torch.cuda.get_arch_list()` (Blackwell: `sm_120`).

### 2. The launcher — CONFIRM

Copy `7.4/comfyui-run.sh` to `~/comfyui-run.sh` on the GPU box, make it
executable, and set `CHAT_MODEL` and `OTHER_GPU_APPS` from *Discover first*.
It keeps two choices from the book:

- **Absolute paths** for Python and `main.py`, so `pkill -f` on the full
  path finds it (see Gotchas).
- **`--disable-smart-memory`**: ComfyUI gives its VRAM back after every job
  instead of holding it. A few seconds a job; the chat model isn't pushed
  onto the CPU in between.

**Verify:** run it in a terminal on the GPU box (CONFIRM: it stops the chat
model). `curl -s localhost:8188/system_stats` answers there, `nvidia-smi`
shows no Ollama model, and `pgrep -af '[m]ain.py --listen'` shows the full
path. Stop it with Ctrl-C.

### 3. The video models — CONFIRM (about 34 GB)

All from Hugging Face, no login needed; **read each model's license** with
the reader first. Into `~/ComfyUI/models/`:

| File | Folder | Source |
|---|---|---|
| `wan2.2_ti2v_5B_fp16.safetensors` (10 GB) | `diffusion_models/` | `Comfy-Org/Wan_2.2_ComfyUI_Repackaged`, `split_files/` |
| `umt5_xxl_fp8_e4m3fn_scaled.safetensors` (6.7 GB) | `text_encoders/` | same |
| `wan2.2_vae.safetensors` (1.4 GB) | `vae/` | same |
| `ltx-video-2b-v0.9.5.safetensors` (6.3 GB, VAE included) | `checkpoints/` | `Lightricks/LTX-Video` |
| `t5xxl_fp16.safetensors` (9.8 GB) | `text_encoders/` | `Comfy-Org/mochi_preview_repackaged`, `split_files/text_encoders/` |

If 7.3's FLUX checkpoint is on this machine, symlink it into
`checkpoints/` rather than keeping two 17 GB copies.

**Verify:** each file's size and checksum match its Hugging Face page.

### 4. The tunnel from the workstation

Source `7.4/comfy.zsh` from `~/.zshrc`, with `GPU_HOST` and `CHAT_MODEL`
set.

**Verify:**
- `comfy` opens ComfyUI at `http://localhost:8188`.
- From another LAN machine, `curl -m5 http://<gpu-box>:8188/` gets no
  answer.
- Ctrl-C ends it; on the GPU box `pgrep -af '[m]ain.py --listen'` prints
  nothing, `nvidia-smi` shows the memory freed, and `ollama ps` shows the
  chat model again within a few minutes.

### 5. The AI skill

Copy `7.4/comfyui-video/` to `~/.claude/skills/comfyui-video/` (or your
assistant's skills folder—`~/.gemini/skills/`, `~/.agents/skills/`—see book
2.3) on the
workstation. Set `GPU_HOST` in `ensure_comfyui.sh`. The four templates in
`templates/` are ComfyUI graphs in **API format** with the model file
names from step 3; if the reader's files differ, change the names there.

**Verify:** ask Claude Code for a 3-second clip with LTX ("a paper boat
drifting down a rain-soaked street"). It runs the preflight (which starts
ComfyUI through the tunnel), runs `comfy_video.py --check`, renders, pulls
frames with ffmpeg, **opens them and says what's off**, and offers a next
step. Then one Wan clip (`--length 61` keeps the test short), and one
image-to-video clip from a still (a 7.3 image is ideal).

Afterwards stop ComfyUI on the GPU box: the preflight's tunnel runs with no
terminal, so killing it may leave ComfyUI running
(`pkill -f '[m]ain.py --listen 0.0.0.0 --port 8188'`), then load the chat
model back.

### 6. Optional: HunyuanVideo 1.5

For clips past 5 seconds that must keep a subject's identity. Native nodes
in current ComfyUI, but the author's graph for it is still experimental
and not in the templates; build it from ComfyUI's own HunyuanVideo 1.5
example, in API format, and add it to the skill. Use the **cfg-distilled
fp8** 720p image-to-video model (the fp16 one is 16.7 GB and doesn't fit a
16 GB card), from `Comfy-Org/HunyuanVideo_1.5_repackaged`, with its two
text encoders, VAE and `sigclip_vision_patch14_384` (that one is at the
root of `Comfy-Org/sigclip_vision_384`). About 21.5 GB. Distilled means
`cfg 1.0` and a negative prompt that does nothing. Frame counts must be
4n + 1.

## Gotchas (from the book and the author's machine)

- **A stop that reports success and does nothing.** Started as
  `./venv/bin/python main.py`, ComfyUI's command line is relative, and a
  `pkill` against the full path matches nothing; the server keeps running.
  On the author's machine that let a PyTorch upgrade land under a running
  server. The launcher uses absolute paths; match on `main.py --listen` to
  be safe either way.
- **Forge never gives its memory back.** A Forge left running from an
  earlier session held 10.5 GB and starved a video render. The launcher
  stops it; starting Forge stops ComfyUI in turn.
- **Without `--disable-smart-memory`**, ComfyUI keeps the last model in
  VRAM; the chat model then runs on the CPU, and on the author's machine
  the two together hit the out-of-memory killer (book 7.5).
- **Upgrading PyTorch needs the full version.** `pip install torch==2.11.0`
  does nothing when `2.11.0+cu128` is installed; pip ignores the part after
  `+`. Write `torch==2.11.0+cu130`. Stop ComfyUI before upgrading.
- **Updating ComfyUI** (`git pull`, then `pip install -r requirements.txt`)
  renames nodes now and then. After an update, run one clip with each
  template.
- **LTX 0.9.5 falls apart past its native length** (97 frames is clean,
  401 is an overexposed blur). The skill chains short segments instead.
- **One prompt for a long clip makes the same shot over and over** (the
  book's war story). Give each segment something to happen.
- **The skill sees frames, not motion.** Flicker and morphing are for the
  reader to judge.

## Rollback

Stop ComfyUI. Remove `~/ComfyUI` (check symlinked model files first, if
Forge uses them), `~/comfyui-run.sh`, the `comfy.zsh` line in `~/.zshrc`,
and `~/.claude/skills/comfyui-video/`. Nothing was opened in the firewall.
