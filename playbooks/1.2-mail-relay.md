# Playbook 1.2 — A mail relay, so the lab can tell you things

> **For the reader.** Read this whole file before you give it to your AI
> assistant. Create an **app-specific password** at your mail provider
> first (never use your account password). Then say: *"Follow this playbook
> on <host>. Ask me before every step marked CONFIRM."* Repeat it for each
> host that should send mail.
>
> **For the AI assistant.** You are helping a reader of *Hand-Me-Down
> Homelab* build what section 1.2 describes. Follow the rules below for the
> whole session.

## Rules for the assistant

1. **Discover, don't assume.** Use the reader's provider, address and host.
2. **Show each command before you run it**, and say which host it runs on.
3. **CONFIRM** means stop, ask, and wait for a yes.
4. **The app password is typed by the reader** into the credentials file
   (see step 3). Never put it on a command line, in your output, or in a file
   you write.
5. **Done means the reader saw the test email arrive**, not "status=sent"
   alone.

## Goal: what "done" looks like

- [ ] Postfix on the host listens on loopback only and relays through the
      provider over TLS with the app password.
- [ ] Mail to `root` (cron, smartd, Proxmox) goes to the reader's real
      address, with a sender address the provider accepts.
- [ ] A test message to `root` arrived in the reader's inbox.

## Discover first

| What | Why | How to find it |
|---|---|---|
| The provider's SMTP host and port | The relay | Provider's docs (the book's is iCloud: `smtp.mail.me.com`, 587, STARTTLS) |
| The reader's account address | The provider accepts mail only *from* addresses on the account | Ask |
| Whether Postfix is already installed | Proxmox and its Debian container template ship it | `postconf -h mail_version` |
| Postfix's own host name | The address-rewrite key must match it exactly | `postconf -h myhostname` |

## Steps

### 1. Packages — CONFIRM

Install **`postfix`** (if missing: choose "Satellite system" or "No
configuration" if asked), **`libsasl2-modules`** and **`bsd-mailx`**.

- Without **`libsasl2-modules`**, Postfix reaches the provider over TLS and
  then fails with `SASL authentication failure: No worthy mechs found`. The
  mail is deferred, not bounced, so nobody hears about it.
- **`bsd-mailx`** provides `/usr/bin/mail`, which smartd's alert hook
  needs (playbook 5.2).
- **Restart Postfix after installing them.** A running Postfix delivery
  process keeps the old libraries: in testing it still said "No worthy
  mechs" until the restart.

### 2. Relay settings — CONFIRM

With `postconf -e`, set: `relayhost = [<smtp-host>]:<port>`,
`inet_interfaces = loopback-only`, `smtp_sasl_auth_enable = yes`,
`smtp_sasl_password_maps = hash:/etc/postfix/sasl_passwd`,
`smtp_sasl_security_options = noanonymous`,
`smtp_tls_security_level = encrypt`,
`smtp_generic_maps = hash:/etc/postfix/generic`.

### 3. The credentials file — the reader types the password

Create `/etc/postfix/sasl_passwd` with mode 600, owned by root, containing
one line: `[<smtp-host>]:<port> <account-address>:PASSWORD-HERE`. Ask the
reader to replace the placeholder with the app password in an editor over
`ssh -t`. Then `postmap /etc/postfix/sasl_passwd`.

**Verify:** both `sasl_passwd` and `sasl_passwd.db` are mode 600. Do not
display them.

### 4. Who the mail is from, and to

- **From:** in `/etc/postfix/generic`, map `root@<myhostname>` to the
  reader's account address, using the value `postconf -h myhostname`
  printed. It's often `<host>.localdomain`, and a key that doesn't match
  exactly rewrites nothing: the provider then rejects a sender it doesn't
  own. Run `postmap /etc/postfix/generic`. **Verify:** `postmap -q
  root@<myhostname> hash:/etc/postfix/generic` prints the account address.
- **To:** add `root: <reader's address>` to `/etc/aliases` and run
  `newaliases`. Without it, mail to `root` is "delivered" to a mailbox on
  this host that nobody reads (`status=sent (delivered to mailbox)`).

Then `postfix check` and restart Postfix.

### 5. Prove it

`echo "test from <host>" | mail -s "relay test <host>" root`, then read the
mail log (`journalctl` filtered to `postfix/smtp`; Debian 13 has no
`/var/log/mail.log` without rsyslog).

**Verify:**
- The log line shows `relay=<smtp-host>` and `status=sent`.
- **The reader confirms the message arrived.**

If it shows `deferred`, the text after `status=deferred` names the
problem:
- `No worthy mechs` → step 1's package or restart;
- `SASL authentication failed; server … said` → the password or the
  account address;
- a rejection mentioning the sender → step 4's generic map.

## Gotchas (from the book and the test)

- **Mail to `root` stays local** without the `/etc/aliases` line, and it
  looks like success in the log.
- **Deferred mail retries silently for days.** `mailq` shows it. Clear test
  junk with `postsuper -d ALL deferred` once fixed.
- **Postfix warns about "backwards-compatible default settings"** on every
  command. It's harmless; `postconf compatibility_level=3.6` quiets it
  after you've read the page it points to.
- **The four ways cron output still dies** (book 5.2): the job redirects its
  output, `MAILTO=""`, no `root:` alias, or it's a systemd timer.

## Rollback

`postconf -e relayhost=` and restart Postfix; remove `sasl_passwd*` and the
`generic` map. Mail to root then stays local again.
