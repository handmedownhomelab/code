# Playbook 1.2 — Proxmox on an old PC or Mac

> **For the reader.** Read this whole file, and `1.2/install-mbpfan.sh` if
> your machine is an Intel Mac, before you give them to your AI assistant.
> The installer itself runs at the machine's own keyboard and screen: you
> do that part (step 2). Then say: *"Follow this playbook. Ask me before
> every step marked CONFIRM."*
>
> **For the AI assistant.** You are helping a reader of *Hand-Me-Down
> Homelab* build what section 1.2 describes. Follow the rules below for the
> whole session.

## Rules for the assistant

1. **Installing Proxmox erases the target disk.** Make sure the reader
   knows that and has copied off anything they want. CONFIRM before they
   start.
2. **Show each command before you run it**, and say which machine it runs on.
3. **Get the ISO from Proxmox's download page and check its SHA256** against
   the published sum.
4. **Verify by effect** (the fan steps: by watching its speed change under
   load).

## Goal: what "done" looks like

- [ ] Proxmox VE runs on the machine, at a fixed address, with its web
      interface reachable at `https://<address>:8006`.
- [ ] On an Intel Mac, the fan speeds up under load (mbpfan), and restarts
      if the daemon dies.
- [ ] One unprivileged container runs from a Debian template.

## Discover first

| What | Why | How to find it |
|---|---|---|
| The machine | Intel Mac or ordinary PC changes step 3 | Ask |
| The address it should have | The installer asks; then reserve it on the gateway (1.5) | Ask |
| The host name it will use | Renaming a Proxmox node later is painful | Ask; pick the final name now |
| What's on its disk now | It will be erased | Ask |

## Steps

### 1. The installer — CONFIRM

Download the current Proxmox VE ISO, check its SHA256 against Proxmox's
published sums, and write it to a USB stick (any image writer; `dd` on
Linux and macOS).

### 2. Install — the reader, at the machine

Boot from the stick. **On a Mac, hold Option at power-on** and pick the USB
device. Follow the installer: target disk, country and time zone, a root
password the reader stores, an email, the **final host name**, and the
address from *Discover first*.

**Verify:** from another machine, `https://<address>:8006` shows the login
page (the certificate warning is expected until book 4.4). SSH as root
works.

### 3. The fan, on an Intel Mac — CONFIRM

Run `1.2/install-mbpfan.sh` from this repository on the host (read it first).
It installs `mbpfan`, reads the fan's own minimum and maximum speeds, writes
the curve (60/70/90 °C, as in the book), and adds the systemd drop-in
`1.2/10-restart.conf` (`Restart=always`), so a crash doesn't leave the fan
stuck.

**Verify:** note the fan speed and CPU temperature, put a minute of load on
all cores, and watch the fan step up within seconds. Then `systemctl kill
mbpfan` and check it comes back by itself.

On an ordinary PC, skip this step: the firmware runs the fan.

### 4. Updates repository

On a machine without a Proxmox subscription, switch to the
**no-subscription** repository as Proxmox's docs describe, then update.
**Verify:** `apt update` shows no 401 errors from the enterprise repository.

### 5. The first container

In the web interface: local → CT Templates → download a Debian template,
then Create CT: unprivileged (the default), one core, 512 MB, a few GB of
disk, DHCP, an SSH key.

**Verify:** `pct list` shows it running, and you can SSH into it.

## Gotchas (from the book)

- **One network port**: every guest shares the bridge `vmbr0`. For
  link-level checks such as LLDP, use the physical interface.
- **Container by default; VM when the software ships as its own OS**, needs
  its own kernel, or you want a hard security boundary.
- **The SMC's automatic fan curve gets no input under Linux** on a Mac.
  Without mbpfan the fan sits at minimum while the CPU climbs.
- **Three names for one machine**: the node name (from the installer, used
  in API paths), its DNS name, and what you call it. Make them agree from
  the start.

## Rollback

Reinstalling the previous operating system is the only rollback for the
install. For mbpfan: `apt remove mbpfan` and delete the drop-in; the SMC
takes the fan back after a reboot.
